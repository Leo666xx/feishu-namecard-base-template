# 拍照自动上传飞书多维表格项目--一键部署

把「拍照上传名片图片 → AI 识别 → 自动拆分成多行 → 字段插件补全」这套飞书多维表格（Base）结构，用 [`lark-cli`](https://www.npmjs.com/package/@larksuite/cli) 复刻到自己的飞书账号。

> 原 Base「名片信息智能管理系统」的核心能力：
> 1. 表单上传 1～5 张名片照片
> 2. AI Agent 看图识别出姓名/职位/公司/电话/邮箱/地址，并生成 OCR 文本
> 3. 字段插件根据 OCR 文本自动补全姓名/职位/公司/电话/邮箱/地址/备注
> 4. 一次上传多张图时，自动拆分成多条有序记录（每行一张图）

## 一、快速开始（推荐：一键安装）

最简方式：在任意终端执行下面这条命令，即可自动处理安装 CLI、授权飞书并初始化 Base：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/你的用户名/你的仓库名/main/install.sh)
```

如果你想先看脚本内容，再决定是否执行，也可以先下载后再运行：

```bash
curl -fsSL https://raw.githubusercontent.com/你的用户名/你的仓库名/main/install.sh -o install.sh
bash install.sh
```

> 注意：授权步骤会打开浏览器，让你登录飞书并确认权限。这个环节是必须的，脚本会在这里暂停等待你完成授权。

## 二、手动安装方式

```bash
# 1. 安装 CLI
npm install -g @larksuite/cli

# 2. 授权（会弹出浏览器让你登录飞书）
lark-cli auth login --recommend

# 3. 克隆本项目
git clone <你的仓库地址>
cd 拍照自动上传飞书多维表格项目

# 4. 一键初始化（在你自己的飞书里生成一模一样的 Base）
./init.sh
```

脚本跑完后，会在你账号里新建一个名为 **「名片信息智能管理系统」** 的 Base，并在最后打印 Base 链接。

> Windows 用户建议在 **Git Bash** 里运行（`npm`、`lark-cli`、`bash` 都需要 shell 环境）；macOS / Linux 可直接用默认终端。

|------|------|
| **Base** | 名片信息智能管理系统 |

## 三、需要手动配置的部分 ⚠️

`lark-cli` 无法脚本化的内容，需要在飞书 UI 里手动补上。**其中第 1 项是整套流程的核心，不做就没有「看图识别」。**

### 1. 识别工作流里的「AI Agent」节点（必做）

脚本只创建了「拆分」工作流，**没有**创建「拍照识别名片信息」识别工作流——因为它的核心是一颗 **AI Agent 节点**，其 prompt / 模型 / 工具 / 输出字段无法通过 CLI 读取或写入（`workflow-get` 里该节点 `data` 为空）。

请在飞书里手动创建：

1. 打开新建的 Base → 自动化 → 新建工作流，命名 **「拍照识别名片信息」**。
2. **触发器**：`添加新记录时`，监控「名片表」的「名片图片」字段。
3. **AI Agent 节点**：这是核心，请照抄你原 Base 里同名节点的配置——
   - 输入：名片图片（附件）
   - Prompt：让 AI 识别名片上的姓名/职位/公司/电话/邮箱/地址，并输出结构化字段 + 一段完整 OCR 文本（写入「图片解析」字段）
   - 输出字段：`姓名`、`职位`、`公司`、`电话`、`邮箱`、`地址`、`图片解析`
4. **修改记录节点**：把 AI Agent 输出的 6 个字段写回当前记录（`姓名/职位/公司/电话/邮箱/地址`）。

> 参考结构见 [`defs/recognition-workflow.json`](defs/recognition-workflow.json)（其中 AI Agent 节点的 `data` 为空，需你在 UI 里补 prompt/模型/工具）。

> 为什么脚本不直接生成这个骨架？因为「触发器 → 空 AI Agent → 修改记录」里，修改记录的取值都引用 AI Agent 的输出字段，AI Agent 没配好之前整条链路是断的，反而容易误导。

### 2. 主字段改为「名片ID」（可选）

原 Base 的主字段是公式字段「名片ID」（自动编号）。飞书 CLI / API 不允许把公式字段设为主字段，所以脚本退而求其次用「姓名」做主字段。

如需还原：表设置 → 把主字段改为「名片ID」。

### 3. 三个 `not_support` 字段（可选）

原 Base 里以下 3 个字段类型无法通过 OpenAPI 读写，脚本无法复刻：

- `WhatsApp破冰`
- `背调状态`
- `开发信2`

如果业务需要，请在飞书 UI 里手动补建。

## 五、常见问题

- **运行报 `未找到 lark-cli`**：先 `npm install -g @larksuite/cli`，确保在 Git Bash 的 PATH 里。
- **`lark-cli auth login` 登录的是企业自建应用吗？**：首次登录会引导你创建/绑定一个 CLI 应用并授予多维表格相关权限，按浏览器提示点确认即可。
- **想改 Base 名**：`BASE_NAME="我的表" ./init.sh`。
- **重复运行**：脚本每次都会新建一个 Base，不会覆盖旧 Base。
